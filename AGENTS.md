# Инструкции для работы с проектом

Этот файл действует для всего репозитория. Общайся с пользователем на русском языке, если он не попросил другой язык.

## Структура

- `OnlineStore.sln` — решение на .NET 8.
- `OnlineStore/` — ASP.NET Core MVC: контроллеры, Razor Views, Areas, middleware и точка входа `Program.cs`.
- `Domain/` — сущности, value objects и спецификации.
- `Application/` — сценарии использования, команды и запросы MediatR, DTO, валидаторы и интерфейсы сервисов.
- `Infrastructure/` — реализации прикладных сервисов.
- `Persistence/` — EF Core, SQL Server, `AppDbContext`, конфигурации сущностей, репозитории и миграции.
- `KeycloakExtension/` — интеграция с Keycloak, клиенты и настройки аутентификации.
- `Resource/` — ресурсы локализации `.resx`.
- `OnlineStore/Scripts/` — frontend на TypeScript и SCSS, сборка Webpack; исходники находятся в `src/`.

## Правила изменений

- Сначала изучи соседние реализации и следуй существующему стилю. Ограничивай изменения задачей пользователя.
- Сохраняй границы проектов и направление зависимостей. Не добавляй зависимости Domain от инфраструктуры или MVC.
- Размещай новые сценарии рядом с соответствующими командами и запросами; используй существующие подходы MediatR, FluentValidation и CSharpFunctionalExtensions.
- Сохраняй nullable-аннотации, используй async/await для ввода-вывода и передавай `CancellationToken` в поддерживающие его вызовы.
- Регистрируй сервисы через существующие `DependencyInjection.cs` и точку композиции приложения.
- При изменении API согласовывай DTO, TypeScript и Razor-представления. JSON настроен на camelCase и строковое представление enum.
- Для локализуемого текста используй ресурсы проекта; поддерживай соответствие ключей в `.resx`.
- Редактируй frontend в `OnlineStore/Scripts/src/`. Webpack генерирует файлы в `OnlineStore/wwwroot/js/`; не исправляй сгенерированные bundle-файлы вручную.
- Не редактируй зависимости в `node_modules/`, результаты сборки в `bin/` и `obj/`, а также автоматически созданные Designer-файлы вручную.
- Сохраняй изменения пользователя. Не выполняй несвязанные обновления пакетов или массовое форматирование.
- Не добавляй пароли, токены и секреты в код, логи или отслеживаемые конфигурации. Используй переменные окружения или подходящее локальное хранилище секретов.

## Команды

Из корня репозитория:

```powershell
dotnet restore OnlineStore.sln
dotnet build OnlineStore.sln --no-restore
dotnet run --project OnlineStore/OnlineStore.csproj
```

Для frontend из `OnlineStore/Scripts/`:

```powershell
npm ci
npm exec -- webpack --mode development --no-watch
npm exec -- webpack --mode production --no-watch
```

Устанавливай зависимости, когда это необходимо. В `webpack.config.js` включён `watch: true`, а `npm run build` дополнительно задаёт `--watch`. Для разовой проверки используй команды с `--no-watch`, чтобы процесс завершился.

Для локального запуска приложение использует SQL Server, Keycloak и конфигурацию Serilog/Seq. Уточняй настройки по коду и локальному окружению, не копируй секреты из конфигурации в ответы.

## База данных

При изменении модели проверь EF-конфигурацию и необходимость миграции. Создавай миграции средствами EF Core, сохраняя согласованность snapshot:

```powershell
dotnet ef migrations add <MigrationName> --project Persistence/Persistence.csproj --startup-project OnlineStore/OnlineStore.csproj
```

Реальная папка называется `Persistence`; в примере команды в README есть опечатка `Persistance`. Не переписывай уже применённые миграции. Применение миграций к общей или рабочей базе должно входить в явно согласованную задачу.

## Проверка результата

- Для изменений C# выполняй сборку решения; для TypeScript/SCSS — разовую сборку frontend.
- Запускай подходящие тесты, если они есть или добавлены в рамках задачи. Успешная сборка не заменяет проверку поведения.
- Для изменений интерфейса по возможности проверяй затронутую страницу, валидацию и ошибки браузера.
- Для изменений только документации достаточно проверить текст, пути и команды; сборка приложения не обязательна.
- В `Infrastructure.csproj` есть ссылка на локальную DLL `Microsoft.AspNetCore.WebUtilities` из runtime `8.0.22`. Если сборка не проходит из-за окружения или зависимостей, сообщи конкретную причину; не меняй эту ссылку вне связанной задачи.
- В итоговом ответе кратко укажи, что изменено, что проверено и какие проверки не удалось выполнить. Не утверждай, что проверки прошли, если они не запускались.
